# 행정사무정보처리용 무인정보단말기(KIOSK) 장애인 편의 기능 표준규격 및 사용자 분석

본 문서는 국가 무인정보단말기(KIOSK) 표준규격 및 장애인 사용자군 분류 데이터를 기반으로 작성된 배리어프리 셀프오더 PWA 개발 표준 명세서입니다.

---

## 1. 무인정보단말기(KIOSK) 분류 체계
- **유통**: 직원의 개입 없이 바코드 스캔 등을 통해 제품 구매 및 서비스 이용 시 사용하는 무인정보기 (예: 무인주유기, 무인결제기, 무인주차정산기, 무인도서대여반납기)
- **주문**: 음식물 등의 주문과 같이 직원의 개입이 필요한 경우 사용하는 무인정보기 (예: 무인주문기 / 셀프오더 키오스크)
- **발권**: 정보처리 후 티켓·서류 인쇄물이 제공되는 경우 (예: 무인민원발급기, 금융자동화기기 ATM, 무인발권기, 셀프체크인)
- **안내**: 정보 제공 중심 (예: 종합정보시스템, 위치정보시스템)
- **기타**: 안면인식 등 신유형 (예: 무인사용자인증기)

## 2. 장애인 편의 기능 표준규격 (차. 장애인 편의 기능 핵심 항목)

| 조항 | 핵심 표준 요구사항 명세 | PWA / 네이티브 구현 반영 방식 |
|---|---|---|
| **3.a** | 각 화면의 안내메시지는 청각장애인을 위한 별도의 안내 기능(자막 등) 및 시각장애인용 음성안내 기능을 제공해야 한다. | 시각 자막 팝업 + iOS VoiceOver / Android TalkBack 표준 ARIA 접근성 탑재 |
| **3.b** | 음성지원시스템 이용자에 대한 이어폰 소켓을 제공하여야 한다. | OS 이어폰 소켓 연결 지원 및 오디오 가이드 지원 |
| **3.d** | 시각장애인용 Keypad (0~9 숫자버튼, '취소'/'정정'/'확인' 버튼 포함)를 부착 및 제공해야 한다. | 폴더폰 및 터치용 0~9 번호 키패드 및 확인/취소 터치 지원 |
| **3.h** | 화면 하단에 "화면확대" 버튼을 제공하여 노인 및 저시력 사용자를 위한 별도의 화면으로 이동할 수 있어야 한다. | 150% 화면 확대 및 초고대비 (Yellow-on-Black) 모드 지원 |
| **3.k** | 시각장애인용 장치들은 정해진 위치(오른쪽 또는 중앙)에 견고하게 장착되어야 하며, 주 조작부 주변 점자 표시를 제공해야 한다. | 정형화된 중앙/오른쪽 조작부 및 점자 햅틱 가이드 반응 |
| **9.a** | 휠체어를 탄 사용자가 앉은 채로 사용할 수 있도록 **바닥면에서 400mm 이상 1,220mm 이하**로 작동부를 부착해야 한다. | **휠체어 전용 모드 (Low-Reach Mode)**: 터치 조작부 88px+ 및 화면 하단 50% 높이 집중 배치 |

## 3. 사용자군 분류 및 편의 기능 매핑

| 사용자군 | 세부 분류 | 주요 편의 제공 기능 |
|---|---|---|
| **시각 장애** | ① 전맹 시각장애인 | iOS VoiceOver / Android TalkBack 스크린리더, 음성안내, 점자 키패드 |
| | ② 저시력 시각장애인 | 화면 150% 확대, 초고대비 (Yellow-on-Black), 굵고 거대한 글자 |
| **난독/고령자**| ① 만 65세 이상 고령자 | 반응시간 보완(시간 제한 완화), 매우 거대한 터치 타겟 |
| | ② 난독증 / 발달장애인 | 정보 단순화, 부가 설명글 제거, 직관적인 단어 및 큰 그림 아이콘 |
| **지체 장애** | ① 하지는 지체 / 휠체어 사용자 | **작동부 높이 400mm ~ 1,220mm** (화면 하단 50% 영역 집중 배치) |
| | ② 상지지체 / 뇌병변장애인 | 터치 미스 보완(Generous Fail-Zone), 큰 48x48+ 버튼 타겟, 디바운스(Debounce 500ms) 적용 |
| **청각 장애** | 청각 / 언어장애인 | 시각 햅틱 펄스, 자막 피드백, 음성 입력 없는 100% 터치 주문, 시스템 경고음 시각적 플래시 및 0.5G 이상 400ms 햅틱 전환 |

## 4. UI/UX 그룹 통폐합 및 세분화 전략 (Architecture Groups)
접근성 렌더링 방식에 따라 내부 아키텍처를 3개 그룹으로 병합(Grouping) 처리하여 시스템 복잡도를 낮춥니다.

### 그룹 A: 선형적 포커스 탐색 그룹 (통폐합 가능)
- **대상**: 전맹 (시각수용 0%), 중증 지체/마비 장애 (터치입력 0%)
- **통폐합 논리**: 시각적 디자인을 완전히 무시하고 오로지 DOM 포커스 순서에 따라 '다음/이전/실행' 1차원 탐색 수행.
- **기술 요건**: 완벽한 시맨틱 마크업, WAI-ARIA 규격 준수 100%, 키보드 트랩 방지.

### 그룹 B: 시공간 해상도 보정 그룹 (미세 조정 필수)
- **대상**: 저시력, 노안, 미세운동장애 (수전증 등)
- **통폐합 논리**: 화면을 보고 직접 터치하나, **크기(시각)**와 **타겟(운동)**에 대한 확대가 필수적임.
- **기술 요건**: 폰트 200~400% 증폭, 고대비, 48x48 이상의 타겟 영역 및 터치 중복 방지 디바운스.

### 그룹 C: 인지 부하 통제 그룹 (통폐합 가능)
- **대상**: 지적/발달 장애, 고령층
- **통폐합 논리**: 정보 처리 병목 보완. 물리적 입출력은 가능하나 인지적 압박을 통제해야 함.
- **기술 요건**: 은유 배제, 단일 화면 내 선택지 4개 이하 제한, 직관적 쉬운 단어, 세션 타임아웃 해제(무제한).

### 공통 보완 요소 (청각 장애)
- 청각/진동 피드백은 특정 그룹에 종속되지 않는 글로벌 토글 속성으로 분리하여 모든 그룹과 병행 적용 가능.
